# DIAG 项目共同定义与实验方向

2026 年 10 月 6 日，用户确定：**DPFR 就是咱们的 DIAG，是同一项工作的实现与论文演进。** 后续工作以当前 DPFR 实现和已完成实验为起点，重新设计、运行 DIAG 论文实验并重写论文。DIAG、DPFR、DIAG-md 均属于用户的工作；DIAG-md 的具体内容与实现对应关系仍需单独核对。

本文是 proposal、implementation、evaluation 三个角色的共同入口。方法身份与任务定义以用户本次决定为准；实现行为以实际代码、展开配置和运行产物为准；论文主张必须由对应实现与实验支持。旧论文及历史记录保留作为可追溯材料。

## 已确定的方法身份

对外论文工作名使用 DIAG。DPFR 是当前实现名和历史实验标识，现有 `dpfr` 模块、配置键、checkpoint、run 名称和路径继续保留。统一身份不要求马上重命名代码。

DPFR 的已有结果属于 DIAG 方法演进中的结果。正式表格应记录具体实现版本与协议，不能因为名称统一就把不同配置的结果混为同一行。也不能把 DPFR 当成独立外部方法与 DIAG 对比；若后续比较新旧实现，应明确作为本方法的版本比较或机制消融。

现有 `DIAG-code/`、`src/diag/` 与 `upstream_BanditPM/dpfr/` 的架构并不因此自动相同。后续论文与实验以当前 DPFR 的实际数据流为实现锚点，旧实现按需要复用或核实。

## 已确定的任务数据流

采用自动离线视频分割：

\[
I_{1:T}\longrightarrow \hat Y_{1:T},\qquad
\mathcal L_{\mathrm{seg}}\text{ 只在有标注的帧集合 }\Omega\text{ 上计算。}
\]

模型可以访问输入片段的全部帧，包括相对于某个输出帧的后续帧。预测覆盖全部输入帧；监督帧集合与预测帧集合分别声明。未标注帧可以参与图像特征、时序上下文和基于图像或预测的辅助约束，但不能把占位掩码当作真实分割标签。

自动分割的前向不接受 GT 点、框、掩码提示或首帧 GT 初始化。训练 GT 用于监督计算；模型自己预测的 mask prompt 属于内部表示，可以使用。依赖人工提示的外部方法应单独注明任务条件。

当前 DPFR 运行消费的是采样后的十帧窗口。全窗口访问不能写成“看过原始视频所有帧”。论文应明确原始视频如何形成片段、源帧编号、片段长度和采样方式。逐帧、因果时序、全窗口方法可以在同一离线任务下评测，需披露访问范围；针对解耦机制的消融还需控制时间访问等条件。

用户已有的病例切分继续使用。重跑前核对切分文件内容与指纹；不重新生成切分，也不因目录缺失而静默替换。

## 当前 DPFR 实现锚点

[模型源码](../upstream_BanditPM/dpfr/model.py) 的前向依次执行：

1. 逐帧 UNeXt 编码并解码 anchor logits，获得当前帧的分割内容。
2. 从 anchor 的前景预测构造 mask prompt；最新运行关闭 GT 替换并 detach 该预测。
3. 图像 token 与 mask token 进入无因果 mask 的全窗口 Transformer，形成各帧上下文。
4. 上下文生成多尺度调制，共享 decoder 再次解码，得到 prompt logits；最新运行使用 `gated_add`。
5. 预测二维空间位移，对 prompt logits 做一次空间 warp，得到 flow logits。
6. 上下文控制的门控融合 anchor、prompt、flow，得到各帧 final logits。

最新运行对 final、anchor、prompt、flow 四路输出在有效标注帧计算分割损失，并加入位移正则。具体权重、优化器、增强、输入尺寸和评测路径见[已核实的数据流手册](dpfr_diag_protocol_manual.md)。其中“DPFR 实际执行”是历史运行事实；“DIAG 重跑建议”以及此前提出的因果约束不属于本次已确定协议，与本文冲突时按本文的任务定义执行。

最新 CAMUS 双 seed 的 test Dice 为 0.93164020、0.93322276，均值为 0.93243148；HD95 尚未补齐。联合训练模型内部 anchor 分支不是独立训练的单帧 baseline。分支差值可以用于诊断，不能代替独立 baseline 的对比。

## 解耦思想与论文主张

DIAG 的研究中心仍是解耦：以当前帧内容为分割锚点，让视频上下文提供条件与修正。两条计算路径是实现结构；内容与时序条件各自发挥什么作用，需要受控实验支持，不能仅凭双分支名称宣称完全解耦。

| 旧论文主张 | 当前 DPFR 的对应事实 | 后续论文与实验要求 |
|---|---|---|
| 当前帧内容与动态条件解耦 | 逐帧 anchor 与全窗口条件调制、空间修正已经存在 | 明确各路径职责，用同协议对照与消融验证作用 |
| PCLF 状态预测与校正、时间间隔建模 | 当前 DPFR 使用全窗口 Transformer，没有该预测校正状态更新或显式真实时间间隔 | 若保留主张，需实现与验证；否则按实际机制重写 |
| HDC 多种互补读出 | 当前 DPFR 有多尺度调制和共享 decoder；不等于旧论文全部 dense prompt、region query 接口 | 区分已实现结构与待增加接口，避免沿用未实现细节 |
| 正增益及群组合性质 | 最新 DPFR 使用加性调制；不能直接套用旧论文正增益组合论述 | 先定义具体变换及可检验性质，再决定是否保留该主张 |

当前空间 warp 与旧论文的 latent state dynamics 是不同机制。旧论文的群组合等代数性质也不自动证明学到了有效运动。旧 PDF 的数值和 H1–H4 是历史主张，不能作为新实现已经实现、通过验收或达到指标的证明。

全窗口上下文可能解释部分性能提升，但目前没有隔离时间访问的实验，不能据现有分数认定它就是提升原因。

## 实验组织与尚待确定的事项

外部对比、机制消融、底座适配分别回答不同问题。外部对比检验 DIAG 与已有方法的任务表现；消融检验解耦、调制、空间修正和融合等机制；底座适配检验方法能否迁移到不同分割架构。普通融合是否作为消融还是外部方法，取决于其来源与要检验的问题，不能预先一概归类。

数据集讨论以 CAMUS、EchoNet Dynamic、EchoNet Pediatric 和 CardiacUDA 为候选基础。尚未冻结最终实验矩阵，也未冻结所有数据集的图像尺寸、窗口采样、底座、训练预算、checkpoint 选择、后处理或指标聚合方式。当前 CAMUS 的十帧、256 输入是已完成运行的配置，不自动扩展为全部数据集的统一要求。

重跑方案仍需落实到可检查的数据流：病例切分 → 源帧与标签出处 → 采样及尺寸 → 视频一致增强 → 前向可见信息 → 有效监督帧及损失 → 验证选权重 → 测试预测及指标。CAMUS 中间帧标签来源、源帧映射、稀疏标签有效性和 HD95 定义应在对应方案中明确。

implementation 阅读本文后，对照当前 DPFR 的前向、标签可见性和训练评估入口，给出实现对应关系与需要修正的缺口。本次熟悉工作不启动训练、不改模型，也不因统一名称改动已有 session。

evaluation 阅读本文后，梳理已有结果的版本、监督与评测条件，区分独立 baseline、联合模型内部 anchor、消融和外部方法。保留历史数值与出处；未满足新协议的结果可用于诊断，不直接转为新论文主表。
